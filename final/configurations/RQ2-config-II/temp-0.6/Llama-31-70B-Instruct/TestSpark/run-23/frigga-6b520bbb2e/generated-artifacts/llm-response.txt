====================== Iteration #1 ======================
1. Unit tests should be written as a separate class in the same package as the class under test.
 2. The test class name should follow the convention: `[ClassUnderTest]Test`.
 3. Each test method should be named according to the test scenario, e.g., `testParseName()`.
 4. Test methods should be public and void.
 5. Test methods should not use `@Before` or `@After` annotations.
 6. Test methods should be written using JUnit 4.
 7. When mocking, use Mockito 5.
 8. Name all methods according to the template: `[MethodUnderTest][Scenario]Test`. Use only English letters.
 9. Use the `@Test` annotation for all test methods.
 10. Use the `@Ignore` annotation for tests that are not yet implemented or not yet ready to run.
 11. Use the `@RunWith` annotation for test classes that use a specific runner, e.g., `@RunWith(MockitoJUnitRunner.class)`.
 12. Use the `@Mock` annotation for mocked objects.
 13. Use the `@InjectMocks` annotation for objects that will have mocked dependencies injected into them.
 14. Use the `@Before` annotation for methods that run before each test.
 15. Use the `@After` annotation for methods that run after each test.
 16. Use the `@BeforeClass` annotation for methods that run before all tests in the class.
 17. Use the `@AfterClass` annotation for methods that run after all tests in the class.
 18. Use the `@Rule` annotation for rules that apply to each test.
 19. Use the `@ClassRule` annotation for rules that apply to all tests in the class.
 20. Use `@Test(timeout = milliseconds)` to specify a timeout for a test.
 21. Use `@Test(expected = Exception.class)` to specify an expected exception for a test.
 22. Use `@Test(expectedExceptions = { Exception1.class, Exception2.class })` to specify multiple expected exceptions for a test.
 23. Use `@Test(expectedExceptions = Exception.class, timeout = milliseconds)` to specify an expected exception and a timeout for a test.
